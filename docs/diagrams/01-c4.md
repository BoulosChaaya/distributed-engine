# C4 model

Three zoom levels of the [C4 model](https://c4model.com): the system in its world,
the deployable parts, then the parts inside the two processes that matter.

## Level 1: System context

Who uses the engine, and what it calls.

```mermaid
flowchart LR
  operator["Operator<br/><i>person</i><br/>runs the platform"]
  tenant["Tenant client<br/><i>software</i><br/>submits work with its API key"]
  engine["Distributed task engine<br/><i>software system</i><br/>accepts, runs and records tasks,<br/>workflows and schedules"]
  external["External HTTP services<br/><i>software</i><br/>called by the http task type,<br/>allow-listed hosts only"]

  operator -- "dashboard, operator API<br/>(Basic auth / operator key)" --> engine
  tenant -- "tenant API (Bearer key)" --> engine
  engine -- "http tasks" --> external
```

## Level 2: Containers

The deployable pieces. The API process also runs three background loops.

```mermaid
flowchart TB
  client["Clients<br/>operator · tenants"]
  web["Web dashboard<br/><i>Next.js</i><br/>login, task and workflow views"]

  subgraph apiproc["API process (Node.js, Express), 3 to 10 replicas on k8s"]
    api["HTTP API<br/>auth · validation · writes"]
    pub["Outbox publisher<br/>LISTEN/NOTIFY + polling"]
    sch["Scheduler<br/>scheduled + cron tasks"]
    rec["Reconciler<br/>re-derives lost queue state"]
  end

  pg[("PostgreSQL 16<br/><b>source of truth</b><br/>tasks · outbox · tenants ·<br/>workflows · schedules")]
  redis[("Redis 7<br/>BullMQ queue · rate limiter ·<br/>worker heartbeats")]
  worker["Workers (Node.js, BullMQ), 5 to 20 replicas on k8s<br/>claim · run handler · record"]

  client --> web
  client --> api
  web -- "operator API" --> api
  api -- "one transaction:<br/>task + outbox event" --> pg
  api -- "rate limit (fails open)" --> redis
  pg -- "NOTIFY outbox_wakeup" --> pub
  pub -- "claim events" --> pg
  pub -- "add job (jobId = taskId)" --> redis
  sch -- "release due tasks" --> pg
  rec -- "find orphans" --> pg
  rec -- "is the job still there?" --> redis
  redis -- "deliver job" --> worker
  worker -- "claim, renew lease,<br/>record result" --> pg
```

## Level 3: Components inside the worker

What one worker does with one job, in the order it does it.

```mermaid
flowchart TB
  job["BullMQ job<br/>{ taskId }"] --> read["Read task row<br/>COMPLETED / FAILED / CANCELLED → skip"]
  read --> tenantchk{"Tenant<br/>suspended?"}
  tenantchk -- yes --> park["Park the job (delayed)<br/>recheck in 60 s"]
  tenantchk -- no --> overlap{"FORBID_OVERLAP<br/>schedule?"}
  overlap -- "lease held" --> wait["Delay 5 s, ask again"]
  overlap -- "free / not needed" --> conc{"Tenant concurrency<br/>lease free?"}
  conc -- no --> defer["Delay 2 s"]
  conc -- yes --> claim["Claim<br/>QUEUED → PROCESSING<br/>new claim token, lease 30 s"]
  claim --> run["Run handler<br/>renew lease every 10 s ·<br/>check for cancel every 2 s"]
  run -- ok --> done["Record COMPLETED + result<br/>(version + token checked)"]
  run -- "transient error" --> retry["QUEUED, retries + 1<br/>BullMQ backoff 2 s, 4 s, …"]
  run -- "permanent / budget spent" --> failed["Record FAILED"]
  run -- "SIGTERM, drain over" --> handback["Hand back as QUEUED<br/>retry not charged"]
```

## Level 3: Components inside the API process

```mermaid
flowchart LR
  subgraph http["HTTP layer"]
    opauth["Operator auth<br/>key / Basic"]
    tenauth["Tenant auth<br/>sha256(key) lookup,<br/>SUSPENDED → 403"]
    rl["Rate limiter<br/>Lua sliding window"]
    routes["Routes<br/>tasks · workflows ·<br/>schedules · tenants"]
  end
  subgraph repos["Repositories (raw SQL)"]
    taskrepo["TaskRepository<br/>acceptTask, transitions"]
    wfrepo["WorkflowRepository"]
    schrepo["ScheduleRepository"]
    tenrepo["TenantRepository"]
  end
  subgraph loops["Background loops"]
    pub["OutboxPublisher<br/>admission · fair pick ·<br/>circuit breaker"]
    sch["SchedulerService<br/>misfire policies"]
    rec["TaskReconciler<br/>advisory try-lock"]
  end
  opauth --> routes
  tenauth --> rl --> routes
  routes --> taskrepo & wfrepo & schrepo & tenrepo
  sch --> schrepo
  pub --> taskrepo
  rec --> taskrepo
```
